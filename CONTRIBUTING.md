# Contributing

Use Node.js 24 or newer and run the test command in the README before proposing a change. The test suite uses temporary databases; keep development data and exports out of commits.

Keep the board readable and the controls compact. Browser preferences belong in view preferences; shared project data belongs in the server and validated domain model. Preserve revision checks, identical-retry behavior, project notes, and the distinction between archive and seven-day deletion recovery.

For an issue, describe the action, expected result, actual result, operating system and Node version. Use a small synthetic example rather than uploading a personal board export. For a pull request, explain the resulting behavior and how you checked it.
